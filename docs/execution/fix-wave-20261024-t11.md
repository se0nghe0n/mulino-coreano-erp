## 제품 변경

Work가 nextAction/nextCheckAt을 명시한 경우, 실제 assessGoal이
현재의 명확한 수량 부족을 입증하면 같은 transaction에
GOAL_QUANTITY_SHORTFALL root와 assignment를 남긴다. 기존 proof
검증을 재사용하되 현재 CommandExecution과 persisted IN_PROGRESS
assessGoal의 ID·canonical hash를 확인하는 전용 내부 경로다.
완료되지 않은 다른 명령이나 QUERY는 사용할 수 없다. root는 원
Goal/조건에 안정적이며 원 proof는 불변이다. 재평가·인계 뒤에도
현재 assignment를 반환한다. 별도 openObligation capability나 grant를
공개·추가하지 않는다. 초기 WORK_NEXT_ACTION을 부족10인 것처럼
대체하지 않는다.

명시적 contribution이 같은 실제 수령의 `[0,90)` 전체를 단위·범위
공백 없이 배분하면 그 receipt의 미배분90 대조 의무만 해소한다.
부분30만으로는 해소하지 않는다. actual occurrence와 원 confirmReceipt
command/hash를 확인하고 원 root·수량·감사를 보존한다. 부족10은
독립 의무다. close는 현재 proof가 UNSATISFIED일 때
REJECTED/GOAL_UNSATISFIED이고, 근거가 미확정이면 기존 HELD를 유지한다.

transferObligation은 제안이며 acceptHandover가 실제 수락이다. 이 두
명령의 scope에 실제 Work item을 포함해 기존 ITEM grant의 모든
차원을 검사한다. grant를 분리·확장하지 않는다. request-contracts의
WORK_ITEM 설명도 이 실제 scope와 동기화했다.

createFollowup은 명시적 draft와 sourceEventId를 받을 수 있다. 현재
같은 item의 raw 온도 관측, 명시적 현행 온도 대응 정책, 발생/기록
시각과 후속 인간 책임을 검사한다. 이 경로는 UNVERIFIED_SOURCE_REVIEW
의무를 만들며 온도 사실을 canonical로 승격하지 않는다. 정상 온도와
상충·정정된 source는 거부/보류한다. 같은 부모·Event의 새 key 재시도도
같은 Work를 반환하고 다른 draft를 보내면 conflict다. 원 CLOSED Work와
과거 assessment는 변경하지 않는다. fixture의 합성 정책을 법규로
표시하지 않는다.

## 입력과 oracle 의미의 수정

가역 layer는 `verification/cases/T11/author_lifecycle_inputs.py`이며
원문 전후는 `lifecycle-input-ledger.json`에 있다. 이전 두 입력 layer도
이 계층을 먼저 엄격히 역변환한다. 알 수 없는 drift는 거부한다.

1. parent에 원래 transfer가 요구한 다음 행동·확인 시각을 명시한다.
   실제 assessGoal 응답의 responsibility.assignments[0].ID를 사용한다.
   quantity는 제품의 decimal 문자열이고 현재 Work revision을 읽는다.
   expiresAt과 별도 acceptHandover를 추가한다. 원래 목표100·수령90·
   부족10·세 종료 사유와 원 assertion은 유지한다.
2. wait의 원래10 BOX/ARRIVED/장소/기한을 보존하며 기존 fixture가
   누락한 pinned Goal·기간·증거 조건을 reviseGoal로 명시한다. 실제
   Receipt.quantity의 verified exists predicate를 쓴다. 증거 없음은
   그대로다. resume-denied의 기대는 공개 WAIT_UNVERIFIED의 HELD다.
   focused PG에서 정확한 WAIT_UNVERIFIED를 확인해 미지원 evaluator가
   대신 통과하지 못하게 한다.
3. unsupported-evaluator의 activate-outcome과 activate-denial-audit는
   현재의 HELD/VERSION_UNSUPPORTED 계약에 맞춘다. 효과0·DRAFT 유지·
   실제 감사1개는 그대로다. evaluator를 지원되는 버전으로 바꾸지 않는다.
4. cancel-after-shipment는 A의 실제 ASSIGN 제안 뒤 B가 acceptHandover로
   수락한다. transfer action ID와 기존 idempotency key를 유지하고
   수락 감사의 capability 기대만 acceptHandover로 고친다. 수락 감사와
   새 assignment의 같은 transaction 기대도 유지한다. close는 현재
   Work revision과 공개 Work/reason slot만 사용한다.
5. closed-followup은 실제 temperature Event ID를 sourceEventId로 쓴다.
   Q100의 W 보유라는 별도 STATE_AT 목표를 명시한다. 부모의 과거
   goal을 복사하지 않는다. 원 owner·다음 행동·확인 시각을 보존한다.
6. shared-scope-partition은 observer 최종 계약의 workId/quantity/
   physicalRange를 비교한다. 실제 Q canonical scope와 같은 occurrence,
   `[0,30)`, `[30,60)`, BOX를 정확히 단언한다. 부모별30과 전체60,
   비중첩 의미를 보존하며 허구의 serial label을 만들지 않는다.

전체110 assertion ID와 모든 T11 fixture·grant·clock·원문·수량은
